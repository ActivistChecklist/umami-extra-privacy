# AI Agent rules

## General rules

* Use pnpm to manage packages.
* This package is consumed via Git dependency (no npm publish yet). Consumers pin a commit SHA in their `package.json`, so every change to `main` is potentially a release. Treat `main` as a published branch.

## Versioning rules (Conventional Commits + SemVer)

This package follows [Conventional Commits](https://www.conventionalcommits.org/) and [Semantic Versioning](https://semver.org/). The commit message determines the version bump.

### Commit message format

```
<type>(<optional scope>): <short description>

<optional body>

<optional footer(s)>
```

### Types and version impact

| Type | Version bump | Use for |
|---|---|---|
| `fix:` | patch (0.1.0 → 0.1.1) | Bug fixes |
| `perf:` | patch | Performance improvements |
| `feat:` | minor (0.1.0 → 0.2.0) | New backwards-compatible features |
| `feat!:` or `BREAKING CHANGE:` footer | major (0.1.0 → 1.0.0) | Backwards-incompatible changes |
| `docs:`, `chore:`, `refactor:`, `test:`, `style:`, `build:`, `ci:` | none | No release-relevant change |

### Breaking changes

For a breaking change, EITHER append `!` to the type (`feat!: drop Node 16 support`) OR add a `BREAKING CHANGE:` footer:

```
feat: rename anonymizeIp options field

BREAKING CHANGE: `salt` option is now required when level is 'hash' or 'geo-hash'.
Previously it would silently fall back to an empty string.
```

### Scope (optional)

Use a scope to indicate which area of the package changed: `anonymize`, `send`, `handler`, `fastify`, `next`, `client`, `deps`.

```
feat(anonymize): add IPv6 mask48 level
fix(fastify): handle missing user-agent header
```

### Examples

```
feat(client): add SendBeacon transport for unload events
fix(send): retry once on transient 502 from Umami Cloud
docs: clarify daily salt rotation in README
chore(deps): bump tsup to 8.4.0
feat!: change default anonymization level to 'mask24'
```

### When to bump the version

After merging changes to `main`, bump `version` in `package.json` according to the highest-impact commit since the last bump:

* Any `feat!:` or `BREAKING CHANGE:` → major
* Otherwise any `feat:` → minor
* Otherwise any `fix:` / `perf:` → patch
* Docs/chore/refactor only → no bump needed

Commit the version bump as `chore(release): vX.Y.Z` and tag it: `git tag vX.Y.Z && git push --tags`. Consumers update by changing the pinned SHA in their own `package.json` to the new tag's commit.

## Testing rules

* IMPORTANT: when adding new pure-logic modules or branches, add vitest tests under `__tests__/` covering the meaningful branches. Tests must pass before commit.
* Tests should be behavior-focused: cover the public API and edge cases that would silently produce wrong answers. Don't write tests for internal helpers that are already exercised through the public surface.
* Skip tests for: trivial glue code, one-line wrappers, type-only changes.
* When adding a non-trivial feature, mention test coverage in your final summary.

## Build rules

* `pnpm build` runs tsup and produces `dist/` (ESM + CJS + d.ts). The `prepare` script runs build automatically when the package is installed as a Git dependency by a consumer.
* `pnpm typecheck` runs `tsc --noEmit` and must pass before commit.
* Do not commit `dist/` — it is generated by consumers' install step.

## Coding security principles

* Never hardcode secrets — use environment variables and document them in the README.
* Use constant-time comparison for tokens and hashes (`crypto.timingSafeEqual`) where applicable.
* Never log raw IPs, tokens, or PII. Anonymization happens inside the handler — callers should not log request bodies upstream of it.
* Validate at boundaries (request handlers). The framework-agnostic core trusts already-validated input.

## Git commit rules

* IMPORTANT: Do not do any automatic commits unless explicitly instructed.
* Do not commit directly to `main`. Open a `dev/NAME` branch and let the human merge via PR.
* Never include Claude or Cursor or the current AI agent in the commit message or as a co-author.
* Do not use stash unless you have to.
